# Designer-maintainable backend localization

Validated on Creatio 10.1.585.0, .NET 8.0.31, PostgreSQL, with clio 8.1.0.130
and FSM package synchronization. The reference originally published at
273eb7531a8284b6072730b097769b95df56a02e resolved backend strings but did not
register them in the designer. This revision registers the normal examples.

## Authoring contract

Use both the source-code schema's B2 declarations and its culture resource XML.
B2 is the serialized LocalizableStrings collection. Its entries contain a stable
UId, A2 (key), A3 (creating schema UId), A4 (modifying schema UId), and A5
(originating package identity). Translated text lives separately under
Resources/<Schema>.SourceCode/resource.<culture>.xml as
LocalizableStrings.<Key>.Value.

SharedGreeting and DefaultOnly are the normal backend examples. The schema is
now UsrAtfLocalizationLabMessages so it can be saved under the default Usr naming
policy. Its UId remains unchanged. Existing consumers of the old example name
must change the schema-name argument to the new name; resource keys are unchanged.
No empty CLR class is needed: the Creatio schema itself owns the resources.

## Diagnostic boundary

RegisteredProbe, XmlOnlyProbe, and MetadataOnlyProbe are explicitly diagnostic.
They must not be copied as the normal authoring recipe.

| Case | Backend strict/current/fallback lookup | Native designer GetSchema |
| --- | --- | --- |
| B2 + XML | Exact translated value in both cultures | Entry with translations |
| XML only | Exact translated value in both cultures | Not listed |
| B2 only | null in both cultures | Entry without values |

Thus direct backend lookup alone is insufficient acceptance. B2 makes the string
part of the designer collection; XML provides its translated text.

## Verification

- 19 stand-free tests cover resources, declaration ownership, resolver behavior,
  domain service and transport boundary.
- 14 real-Creatio tests cover strict/current/fallback lookup, missing/default-only
  values, the diagnostic matrix, the Freedom UI resource bundle, designer discovery,
  and a native SourceCodeSchemaDesignerService GetSchema -> SaveSchema -> GetSchema
  round trip preserving the complete declared string collection and translations.
- Spanish was explicitly activated before package synchronization.
- Distinct English/Spanish probe values prevent the old literal from passing as
  proof of newly deployed resources.
- Designer service discovery and save/readback were verified against the live
  instance. Visual browser validation of Configuration was unavailable because the
  browser blocked the Configuration route. No screenshot-based claim is made.
- The exclusive disposable instance was removed after validation; registration,
  deployment directory, IIS site/pool and database absence were checked.

Run the commands in README.md against an exclusive, writable development instance.
The live save test requires the package to be unlocked and the schema name to comply
with that instance's configured prefix. It saves the loaded schema without changing
its values; the application must not be edited concurrently.

## Deployment observations and limits

The old empty owner CLR class was compiled twice, from Schemas and Autogenerated,
causing CS0101. Removing that unnecessary class fixes the reference's duplicate.
A package compile could report success while the new endpoint or resource values
remained stale; a runtime restart then exposed them. Assert runtime values rather
than interpreting compile success as proof. The initial FSM enablement could race
its restart; the supported pkg-to-file-system retry completed the export.

This evidence covers the stated FSM workflow and platform version. It does not
establish XML-only preservation after designer editing, non-FSM installation,
other platform versions, or a universal Freedom UI resource registration rule.
The canonical guidance owner remains clio-knowledge's localizable-values article.
